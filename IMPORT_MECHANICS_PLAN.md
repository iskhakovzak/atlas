# Общая механика импорта Atlas

Дата: 8 октября 2026. Проектный план по текущему коду релиза 152; не заявление о готовности всех магазинов. Реализация и публикация этого плана ещё не выполнены.

## Что уже есть и чего не хватает

В `lib/importer/extract.ts` есть варианты с ID, размером, цветом, ценой и наличием, а также галереи расцветок. `lib/importer/link-selection.ts` показывает всю группу и формирует точную ссылку выбранного варианта специально для eBay; остальные источники преимущественно привязаны к исходной расцветке. Нельзя просто снять это ограничение для всех доменов: разные цвета могут быть отдельными товарами, а одноимённые варианты — разными предложениями продавцов.

`ProductVariant` пока недостаточно явно описывает независимые параметры, регион, продавца и точную ссылку дочернего варианта. Цвет в галереях сопоставляется по тексту. `availabilityKnown:false` существует, но не должен трактоваться как разрешение автоматической покупки. Админский `importDraft` использует общий результат импорта; старые ручные подтверждения и публикация черновиков требуют отдельного совместимого перехода.

## Одинаковое поведение покупателя и администратора

1. Пользователь вставляет ссылку. Проверяются магазин, HTTPS, регион и точный товар/вариант. Параметры выбора сохраняются; рекламные параметры не становятся идентификаторами товара.
2. Обработчик магазина получает подтверждённую группу и реальные сочетания параметров. Родственные товары не собираются по похожему названию или картинке.
3. Показываются только сочетания с подтверждённым наличием, точной ценой/валютой и проверяемым ID. Недоступные и неизвестные по наличию варианты не добавляются в выбор. Если данных нет, показывается понятная причина и автоматический повтор; отсутствие ответа не означает «распродано».
4. Каждая расцветка показывает свою цену либо диапазон. После выбора всех параметров показывается точная цена этого сочетания. Верхняя цена следует просматриваемому варианту; общий расчёт отдельно учитывает все выбранные позиции.
5. Смена цвета переключает его галерею и доступные размеры. Сохранять размер можно только если точно такое сочетание существует; иначе размер сбрасывается. Нельзя незаметно выбирать соседний размер или другую ширину.
6. Формат размера меняет подпись, но не SKU. US/UK/EU/CM преобразуются только по подтверждённой таблице бренда, пола, возраста и категории. Длина стопы не смешивается с длиной стельки или маркировкой CM магазина. Если таблицы нет, сохраняется исходный размер продавца.
7. Покупатель может выбрать несколько сочетаний. Каждая строка получает свой SKU/предложение, ссылку, цену, валюту, цвет, параметры и фото. Просмотр другого цвета не меняет уже выбранные позиции.
8. Перед добавлением сервер сверяет каждый точный вариант с магазином. При исчезновении варианта он не подменяется. При изменении цены новый расчёт явно показывается; прежнее согласие не считается согласием на более дорогую покупку. Ручное подтверждение корректности импортированных данных не требуется.

## Общий контракт данных

Нормализованный снимок группы: магазин, регион, страна назначения, валюта, точный groupId, исходная ссылка, время проверки, полнота результата и источник данных.

Для каждого сочетания: productId, variantId/SKU, при необходимости sellerId и offerId; точная sourceUrl; исходные параметры `{name, value}` и стабильные option IDs; colourId; цена, валюта и условия применимости; наличие `in_stock / out_of_stock / unknown`; количество только если магазин его сообщил; собственная галерея или подтверждённая ссылка на галерею colourId. Отдельно сохраняются исходные и отображаемые значения размеров.

Обязательные правила:

- Не создавать декартово произведение отдельных списков цветов и размеров: принимать только реальные SKU.
- Уникальность: магазин + регион + товар + вариант + продавец/предложение. Текстовый label не служит ключом.
- Не сопоставлять галереи по позиции в массиве, общему названию цвета или догадке по изображению.
- Один источник снимка для ID/цены/наличия. При дополнении данных другим источником проверять идентичность и свежесть.
- Не заменять цену варианта минимальной ценой группы. Персональная скидка, купон, подписка и цена участника не становятся обычной ценой без подтверждения применимости.
- Не смешивать разные валюты или региональные группы. Конвертация и доставка рассчитываются сервером по действующим правилам Atlas.
- Неполная страница результатов не объявляется полной группой. Ограниченная пагинация и лимиты; подтверждённые полученные варианты можно показывать с указанием неполноты.
- Если фото конкретной расцветки отсутствует, не подставлять фото другой. Для автоматической публикации нужна корректная фотография; неполная карточка ждёт повторной проверки.

## Источники, американский IP и сбои

Порядок получения: доступный официальный/партнёрский источник с подтверждёнными правами и нужными полями; затем структурированные данные самого магазина; затем его публичная карточка. Отдельно проверять доступность, условия и полноту каждого источника перед подключением. Наличие магазина в allowlist не означает, что импорт прошёл проверку.

US egress — часть контекста запроса, вместе с регионом сайта, валютой и адресом/индексом склада. Он не гарантирует отсутствие блокировки. Zara Spain и европейские витрины сохраняют свой регион даже при американском исходящем IP. Источник может показывать товар в наличии, но не доставлять на нужный склад: это отдельная проверка.

Сохранять существующую защиту URL, редиректов и изображений, таймауты, конечные бюджеты тела/страниц/вариантов. Параллелизм ограничить по магазину. Повторять только временные ошибки с задержкой и учётом Retry-After, без бесконечных циклов. Статусы: загрузка, готово, частично, временно заблокировано, источник недоступен, товар закончился. CAPTCHA/403 и неизвестное наличие никогда не дают фиктивную цену или положительное наличие.

Кэш включает магазин, регион, валюту, контекст доставки и идентичность группы; рекламные параметры не создают дубликаты. Выбранный вариант применяется отдельно к снимку группы. Просроченный снимок нельзя использовать как свежую проверку перед корзиной. Объединять одновременные одинаковые запросы, сохраняя ограничения доступа и частоты.

## Админский импорт «вставил ссылки → результат»

Пакет ссылок обрабатывается независимой очередью: проверка → импорт группы → нормализация → проверка качества → публикация готовой карточки либо ожидание автоматического повтора. Сбой одной ссылки не останавливает остальные. Повторный импорт обновляет ту же группу; варианты не создают дубликаты карточек.

К автоматической публикации допускается только подтверждённая карточка с точной идентичностью, ценами/валютой, доступными сочетаниями и корректными фото. Веса по категории остаются явно оценочными, неизвестная доставка получает существующий резерв, а не ноль. Не требуется ручное подтверждение данных для качественного результата. Недостаточные данные не обходятся ручной галочкой «всё верно»; они остаются в очереди с причиной. Существующий редактор для правок сохраняется.

Обновление не должно стирать редакторские описания и коллекции. Новый снимок сохраняется атомарно; пропажа части ответа не считается массовой распродажей. Подтверждённо недоступные SKU исключаются из новых покупок, но прошлые заказы сохраняют свои снимки. Для фоновой очереди и периодических проверок отдельно реализовать надёжный запуск, идемпотентность, повтор после сбоя и журнал; сам файл worker не доказывает, что расписание подключено.

## Критерии готовности каждого магазина

Нужны реальные контрольные ссылки: несколько цветов с разными ценами; разные цены по размерам; исчезнувший вариант; нулевое/неизвестное наличие; ссылка сразу на дочерний вариант; все характерные дополнительные параметры; другой регион; разные фотографии; групповая и частичная выдача.

Проверить цепочку целиком: ответ магазина → нормализованный снимок → UI → корзина → свежая серверная сверка → админский черновик/публикация/повторное чтение. Каждый ID, цена, валюта, параметр и галерея должны соответствовать одному варианту. Отдельно проверить мобильную версию, количество и общую сумму нескольких вариантов, смену цены, устаревший кэш, повторную ссылку, сбой одного товара в пакете, редиректы и чужие изображения. Для маркетплейсов — смену продавца/состояния, для одежды — независимые оси размеров.

Перед релизом: lint, полный существующий набор тестов, TypeScript и build, плюс живые проверки из подтверждённого US-контекста. Фикстуры не доказывают, что магазин доступен сейчас; UI с перехваченными ответами не доказывает реальное сохранение в админке. Доступность внешних источников и необходимость партнёрских ключей фиксировать честно по каждому магазину.
